# Agent Runtime Kit v0.2.0

## Highlights

- Map native LangChain/LangGraph messages, tool calls/results, stable IDs and usage, with
  equivalent tool-capable Runnable/StateGraph examples and strict unsupported-content errors.
- Scope runtime continuation, history and replay to the configured namespace; optional unscoped
  store access remains a trusted maintenance facility, not tenant authorization.
- Correlate request/run/thread/trace logs and runtime/agent version spans without exporting raw
  exception text by default.
- Drain or cancel in-flight invocations through bounded `runtime.shutdown()` before disposing
  host resources, verified with real container SIGTERM and post-restart replay.
- Install and migrate using only the wheel's `postgres` extra and packaged migration commands.
- Commit generated history, successful status, and replayable response atomically.
- Apply one cooperative invocation deadline across policy, model/tools, and persistence, with
  separately bounded cleanup and safe cancellation/uncertain-commit handling.
- Reject overlapping same-thread turns across processes with retryable `thread_busy` conflicts.
- Fence owners with finite database-clock leases and recover abandoned work to explicit terminal
  failure without automatically repeating external side effects.
- Validate installed wheels independently, including real child-process termination and v0.1.1
  data preservation. Release publication is gated on fresh/upgrade consumer validation.

## Breaking Changes and Upgrade

Schema revision advances to `0002`. Drain/stop all old workers before migrating; mixed-version
rolling deployment is unsupported. Successful responses, history, feedback, and memory remain
intact. Legacy active runs become `legacy_owner_unavailable` failures, not inferred successes.

Custom `RunStore` implementations must support atomic completion, owner tokens, lease-aware
thread arbitration, conditional cleanup, and `recover()`. Invocation timeout now includes phases
previously outside the budget; account for the additional cleanup budget.

Custom `MemoryStore` implementations must accept the `namespace=` keyword on conversation
lookup/read/append. Hosts must call `runtime.shutdown()` after ingress drain and before closing
model clients, database engines or telemetry. `RuntimeClosingError` maps to retryable HTTP 503.

Read [the upgrade guide](https://github.com/Shengtao-Lin/agent-runtime-kit/blob/main/docs/upgrading-to-v0.2.0.md)
before adopting this version. Canonical request/response contract `v1` remains unchanged.

## Scope and Limits

The importable library remains the product; HTTP service and fictional agent are optional.
Authentication, authorization, tenancy, backups, and deployment controls belong to the host.
Cancellation is cooperative, not a hard real-time bound or rollback of external tools. Recovery
requires a retry/new claim or application-owned sweep and never guarantees exactly-once effects.
Deterministic provider contracts are tested; this is not a live-provider or performance certification.
Distribution remains GitHub wheel/source artifacts and GHCR, not PyPI.
Built-in LangChain/LangGraph wrappers retain terminal streaming fallback; native/provider
incremental streaming is available. No framework-specific incremental stream is promised here.
