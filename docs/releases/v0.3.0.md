# Agent Runtime Kit v0.3.0

These notes describe the v0.3.0 release artifact. Publication is confirmed by the GitHub Release,
not the version metadata or the presence of this document.

## Highlights

- Opt into LangChain message-chunk and LangGraph messages/values incremental streaming using
  the existing canonical Python/SSE contract. Default adapter constructors retain terminal fallback.
- Supply custom stream mappers for application-owned event/state shapes and filter graph text
  by public node metadata. Full framework state is never emitted directly as transport events.
- Close underlying streams on cancellation, abandonment and downstream backpressure; commit only
  complete accepted output and replay terminal results without repeating model/tool execution.
- Validate application-owned real Runnable/StateGraph integrations from independent installed
  wheels, including tools, custom state, history, feedback, safe errors and shutdown.
- Resolve clean lower/latest dependency profiles on Python 3.11/3.12; retain exact requirements,
  inventories, JUnit/provenance and synthetic performance reports.
- Probe real database pool exhaustion, row-lock waits and terminated idle backends.
- Gate publication on preserved-data upgrades from both v0.1.1 and the checksum-pinned v0.2.0 wheel,
  including stable existing ownership leases, canonical replay and framework streaming acceptance.

## Compatibility and Adoption

The `adapters` extra now requires LangGraph >=1.2.11,<2. An older 0.2.28 cancellation probe
left an internal queue task pending after the outer iterator closed, so it is not certified for
this release. Resolve a compatible LangChain Core alongside it; independent bounds are not a
promise that every core/graph combination is installable. Upgrade framework dependencies before
enabling incremental mode. Older v0.2.0 consumers can retain their historical dependency set.

Canonical contract `v1` and schema `0002` remain unchanged. No migration is added over v0.2.0.
For upgrades from v0.1.1 follow the v0.2.0 drained-worker upgrade guide first.
See [the v0.3.0 upgrade guide](../upgrading-to-v0.3.0.md) for the current-release path and its evidence.

Incremental mode requires an underlying `astream()` and the `adapters` extra for built-in native
message translation. `invoke()` behavior remains unchanged. Review the framework runbook before
enabling streaming: the Runnable default handles one message stream or one terminal state, graph
defaults consume v1 messages/values tuples, and default tool events arrive with final normalized
output. Use explicit stream mapping for earlier tool events, multi-message streams or custom APIs.

Text deltas are provisional. Node filtering affects only deltas, not persisted/final content.
Cooperative deadlines, cleanup budgets and external side-effect limitations still apply.

## Validation Boundaries

Dependency profiles are tested combinations, not every possible permutation. Synthetic timings
include PostgreSQL/tracing overhead and are not a live-provider SLA, sustained-load certification
or a regression threshold. Provider credentials are not required by CI. Distribution remains
GitHub Releases and GHCR; PyPI is not configured.
