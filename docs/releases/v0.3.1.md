# Agent Runtime Kit v0.3.1

This patch release hardens the existing provider boundary. Contract `v1`, schema `0002` and
provider constructor compatibility are unchanged. No new migration or automatic retry is added.

## Fixes

- Premature provider EOF is no longer mistaken for successful completion. OpenAI-compatible
  streams require `[DONE]`, Anthropic requires `message_stop`, and Gemini requires `STOP`.
- Explicit stream errors and reported unsuccessful finish reasons fail rather than persisting
  provisional text as a complete answer. Gemini finish-only frames remain supported.
- Decoded responses/streams are bounded to 8 MiB and individual SSE events to 256 KiB. Split UTF-8,
  multiline fields and LF/CRLF framing are handled without delaying small text deltas.
- HTTP retry hints distinguish transient statuses/transport failures from authentication, request,
  malformed-data and size-limit failures. The stable error code remains `provider_failure`.
- Provider responses close on failure and consumer teardown; injected clients stay host-owned.

## Adoption

Some compatible proxies previously accepted by accident may omit valid stream completion or SSE
framing. Those responses now fail closed. Update the proxy or supply an application-owned model
client with explicit protocol handling; do not convert partial text into durable success.
Reported length/safety stops are rejected because the canonical result does not represent partial
or filtered outputs. A failed runtime idempotency key is not automatically reexecuted, regardless
of its provider retry hint. Inspect durable state and tool effects before starting new work.

See the [provider runbook](https://github.com/Shengtao-Lin/agent-runtime-kit/blob/v0.3.1/docs/runbooks/model-providers.md)
and [upgrade guide](https://github.com/Shengtao-Lin/agent-runtime-kit/blob/v0.3.1/docs/upgrading-to-v0.3.1.md).
Tests use synthetic transports and real PostgreSQL; no live model or provider account certification
is claimed. Distribution remains GitHub Releases/GHCR, not PyPI.
