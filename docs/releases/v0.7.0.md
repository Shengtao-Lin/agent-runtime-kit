# Agent Runtime Kit v0.7.0

This release adds explicit incremental history reads for applications that retain long durable
conversations while selecting a smaller initial agent context. Default behavior remains unchanged.

- Enable `AgentRuntime(stream_history=True, context_window=...)` on a capable memory store. The
  optional `StreamingMemoryStore` protocol and `ContextWindow.select_stream` are independently
  importable; unsupported explicit configurations fail during construction.
- PostgreSQL uses one ordered cursor snapshot and complete column rows. Incremental selection
  preserves all historical validation, old system messages, current input, whole tool exchanges
  and message order. Runtime closes cursors before hooks and agent execution, including on failure
  and cancellation. Complete durable history and exact saved replay are unchanged.
- The independent Stage E workload compares actual v0.6.0 and the development implementation across
  three repetitions, 42 processes and 510 continuations each. Every final candidate budget passes;
  10,000-turn invoke/first-text p95 values are below 1.48 seconds with about one MiB measurement RSS
  growth. Absolute RSS and diagnostic overhead are recorded separately. Rejected experiments remain
  available; some medium-history profiles are slower.
- CI retains existing compatibility, import, provider, upgrade and container gates, adds explicit
  incremental smoke, and verifies actual v0.6.0 context-policy/state upgrades. Native and real
  LangChain/LangGraph consumers cover snapshots, corrupt old rows, cancellation, timeout, contention,
  replay and resource cleanup.

Every historical row is still scanned, transferred and validated. Row batches do not bound payload
bytes; pending tool state and later model inputs remain workload-dependent. This is not a production
SLO, universal RSS bound, token limit, summarizer or selective retrieval system. Canonical `v1`,
PostgreSQL schema `0002` and dependency ranges are unchanged.
