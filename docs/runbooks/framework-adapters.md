# Framework Adapter Runbook

## Purpose and Ownership

Framework adapters translate between canonical `InvocationInput`/`InvocationOutput` and a
framework-owned runnable or graph. `NativeAgentInvoker` owns the built-in model/tool loop.
`LangChainRunnableAdapter` and `LangGraphAdapter` wrap public async framework objects through
explicit edge mappers.

Adapters do not own durable conversation history. PostgreSQL remains the source of truth, and the
runtime supplies prior messages before invoking an adapter.

## Prerequisites and Installation

```bash
uv add "agent-runtime-kit[adapters,postgres] @ git+https://github.com/Shengtao-Lin/agent-runtime-kit@v0.1.0"
```

Before registration, decide:

- the stable public agent ID and semantic implementation version;
- the capability names returned through discovery;
- the exact framework input shape; and
- how the framework result becomes only the newly generated canonical messages and tool results.

## Adapter Selection

| Adapter | Use when | Streaming behavior |
| --- | --- | --- |
| `NativeAgentInvoker` | You want the kit's bounded provider/tool loop | True incremental streaming when the model client supports it |
| `LangChainRunnableAdapter` | You have an async object with `ainvoke()` | Non-streaming fallback unless a custom streaming invoker is implemented |
| `LangGraphAdapter` | You have a compiled async graph with `ainvoke()` | Non-streaming fallback unless a custom streaming invoker is implemented |

All three satisfy the same registry and runtime contracts.

## Integration Workflows

### LangChain runnable

```python
from agent_runtime.adapters import LangChainRunnableAdapter

adapter = LangChainRunnableAdapter(
    agent_id="support-langchain",
    version="1.0.0",
    runnable=runnable,
    input_mapper=to_runnable_input,
    output_mapper=from_runnable_output,
    capabilities={"support"},
)
agents.register(adapter)
```

### LangGraph graph

```python
from agent_runtime.adapters import LangGraphAdapter

adapter = LangGraphAdapter(
    agent_id="support-langgraph",
    version="1.0.0",
    graph=compiled_graph,
    state_input_mapper=to_graph_state,
    state_output_mapper=from_graph_state,
    capabilities={"support"},
)
agents.register(adapter)
```

The default mappers handle canonical message dictionaries. Supply explicit functions whenever the
wrapped object uses custom state or output types. Keep these functions pure and cover captured
shapes with synthetic unit tests.

## Mapping Contract

An input mapper receives the complete `InvocationInput`, including prior history, new messages,
runtime context, and metadata. An output mapper receives the framework result plus the original
input and must return `InvocationOutput`.

The output must contain only messages generated by this invocation. Returning input history again
causes duplicated durable messages. Do not configure persistent LangChain memory or a persistent
LangGraph checkpointer alongside the runtime's PostgreSQL history.

## Verification

```bash
uv run pytest tests/unit/test_adapters.py tests/unit/test_native.py -q
```

For each application adapter, add tests for:

- the minimum valid framework result;
- multiple generated messages;
- malformed or unexpected framework output;
- exception translation without sensitive error leakage;
- prior history appearing exactly once; and
- async cancellation reaching the wrapped object.

Discovery should report the configured ID, version, framework, and capability set. Invocation
through the Python runtime and optional HTTP service should produce the same canonical response
shape for every implementation.

## Streaming Expectations

The runtime accepts both `AgentInvoker` and `StreamingAgentInvoker`. Calling `runtime.stream()` on
a non-streaming adapter is supported, but it yields `started` followed by `completed` without text
deltas. Implement the optional streaming protocol only when the underlying framework provides a
stable incremental API and the adapter can still produce one terminal `InvocationOutput`.

## Troubleshooting

### Mapping fails after a framework upgrade

Capture the new input or output shape using synthetic data, update the explicit mapper, and pin the
framework version until the tests pass. Do not expose raw framework exceptions to public callers.

### Agent registration is rejected

Agent IDs are unique. Correct startup configuration or choose a distinct public ID; do not replace
registry entries dynamically while traffic is active.

### Conversation history appears twice

Remove framework-owned persistent memory or checkpointers and confirm the output mapper excludes
the messages present in `InvocationInput`.

### Streaming has no text deltas

This is expected for the built-in LangChain and LangGraph adapters. The terminal response remains
valid. If incremental delivery is required, implement and test `StreamingAgentInvoker` around the
framework's public streaming interface.

### Cancellation leaves work running

Ensure the wrapped framework and any downstream tools propagate async cancellation. Bound external
calls independently so a cancelled runtime request does not leave unlimited background work.

## Security and Upgrade Notes

Mapper code is a trust boundary: it may see the full message history and metadata. Do not log raw
objects. Use public framework APIs, pin supported version ranges, and repeat contract tests before
upgrades. Framework-native persistence must not compete with runtime-owned PostgreSQL state.
