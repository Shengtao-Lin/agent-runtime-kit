# v0.3.1 Candidate Readiness

This is pre-publication evidence, not a claim that version metadata constitutes a release.
Schema `0002`, canonical contract `v1` and provider constructors remain compatible.

## Scope and findings

New offline regressions reproduced premature completion for EOF in all three providers and ignored
stream errors in OpenAI-compatible/Anthropic clients (five failing cases before the fix).
Protocol completion, error detection and unsuccessful finish handling now fail closed. Bounded
HTTP/SSE decoding preserves incremental delivery, response cleanup and injected client ownership.
Provider errors retain their public code while exposing more accurate per-instance retry hints.
No automatic invocation/tool/provider retries are introduced.

Reports are generated under `build/v031-provider-wheel`, `build/v031-upgrade` and
`build/release-desk-v031-candidate`. The provider runner checks installed version, module path and
non-editable wheel provenance, and retains the resolved package inventory with JUnit results.
It shares committed public-behavior fixtures with unit tests; this is package acceptance, not an
independent vendor certification. No live model credentials, customer data or paid calls are used.

## Publication gates

CI and Release run the installed provider fixtures and preserve actual v0.3.0 upgrade evidence,
in addition to historical v0.1.1/v0.2.0 paths. Library/metadata changes also run the standalone
application PR matrix. Publication remains immutable-tag-push-only after all release gates pass.
After publication repeat acceptance with actual downloaded assets and record their digests.

The SSE bounds apply to decoded bytes read by the adapter, not a hard process-memory limit on
third-party transports. EOF/errors produce no successful response or partial persisted messages.
Retryability is advisory and does not override failed-key replay or external side-effect limits.
