## Promotion gates and boundaries

Exact-head PR and main CI, nonpublishing Release, independent application and lower/latest probes
must pass before creating a new immutable v0.4.0 tag. The tag workflow repeats exact-wheel fresh,
provider and four-source upgrade acceptance plus container SIGTERM before publication.
After publication install actual downloaded assets in fresh external venvs, repeat current-release
upgrade/application checks and verify artifact digests/image identity. Preserve immutable tags.

The default application lock is still the historical published v0.3.0 wheel; candidate mode is an
explicit separate install. Update the lock only after the intended new release actually exists.
Memory checkpoints are informational and not RSS or long-term regression thresholds. A managed
lifetime is not an ingress drain, hard process kill, tenant boundary or automatic recovery system.
