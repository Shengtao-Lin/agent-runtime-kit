# v0.4.1 Candidate Readiness

This report records pre-publication evidence, not proof that a release exists.
Public signatures, dependency ranges, canonical contract `v1` and schema `0002` are unchanged.

## Confirmed issues and correction

The initial 58-case offline batch reproduced 23 failures against v0.4.0: four direct-call paths
leaked raw canonical text validation, absent/partial usage invented zeros, numeric strings were
coerced into counts, and OpenAI/Gemini alternatives were merged or dropped. The expanded regressions
cover unknown/null/zero/invalid usage, canonical text and content-part limits, response-stream closure,
no terminal success on failure and the supported single-candidate index boundary.

Main CI subsequently exposed a pre-existing Windows queue-teardown test race: its 50 ms invocation
budget could expire before the queue reached the asserted full state. An 80 ms synthetic startup
delay reproduced the exact timeout locally. The test now isolates its invocation budget from the
unchanged two-second deadlock guards, checks `invocation_cancelled` and always shuts down resources.
It covers immediate and delayed startup without changing runtime production code.

Shared private canonical validation now makes safe `ProviderError` available without `AgentRuntime`.
Unknown usage stays unknown; supplied counts are checked without coercion. No public model limit is
increased. Anthropic cumulative counts replace previous values rather than being added together.

## Promotion gates

Require exact-head PR CI, lower/latest compatibility, independent application checks and nonpublishing
Release verification, then main CI/Release verification before tagging. CI/Release retain historical
v0.1.1/v0.2.0/v0.3.0/v0.3.1 paths and add actual SHA-256-pinned v0.4.0 state preservation. Tag gates
repeat quality/full pytest, exact-wheel fresh/provider/five-source upgrades and container SIGTERM.

After publication download/hash-check actual target assets and verify GHCR identity; rerun provider
and v0.4.0 upgrade acceptance from that exact wheel. Only then update the independent application
lock, retaining candidate/published separation. No live provider calls, credentials or model-quality
claims are involved. Short synthetic soak evidence is not a production SLA or long-term memory proof.
