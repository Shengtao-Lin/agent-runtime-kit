## Adoption and limits

Release Desk's own manifest/lock remains pinned to actual published v0.4.1. Its candidate v0.4.2
application checks passed, but that is not an assertion of published-v0.4.2 lock adoption.

Subsequent adoption on 2026-10-29: PR #35 pins actual v0.4.2 without unrelated dependency changes.
The [application workflow](https://github.com/Shengtao-Lin/agent-runtime-kit/actions/runs/40899895130)
passed all three matrix entries (published Python 3.11/3.12 and candidate 3.12). The published 3.12
job passed eight tests and a read-only v0.4.2 metadata canary: six checks, exact cross-process replay,
four history messages and idempotent feedback. Artifacts retain provenance and `public-canary.json`.
The preceding v0.4.1 status describes the original publication checkpoint, not current adoption.

No live model calls, paid provider operations or PyPI setup were used. This is not complete vendor
protocol certification, model-quality evaluation, long-duration stability testing or a production
throughput/SLA claim. Short synthetic soak allocations are not process-RSS certification. Native
usage changes do not rewrite historical replay responses or reinterpret framework usage envelopes.
