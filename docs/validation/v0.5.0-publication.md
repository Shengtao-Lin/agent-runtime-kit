## Independent application adoption

Release Desk's own manifest and lock pin the actual v0.5.0 asset URL and wheel digest above.
No unrelated dependency versions changed. Its provenance test verifies installed version/URL,
non-editable library location and the independently locked asset checksum.

`scripts/validate_release_desk.py --live --report-dir build/release-desk-v050-published` installed
from that lock outside the checkout on a separate disposable PostgreSQL database. Eight application
tests passed. The public v0.5.0 metadata canary passed six checks, exact cross-process restart replay,
four history messages and idempotent feedback. The report directory retains `package-audit.json`,
`installed-packages.txt`, `results.xml` and `public-canary.json`.

The public canary reads metadata only; it does not execute downloaded release artifacts as business
logic. Independent installation/upgrade tests above establish actual artifact behavior. Application
CI still runs the published Python 3.11/3.12 and candidate Python 3.12 matrix before merging adoption.

## Limits

Synthetic tool/model fixtures and short soak runs do not establish production capacity, model
quality, universal vendor compatibility or exactly-once external effects. Live provider credentials,
paid operations, PyPI publishing and Stage D context/workload policy are outside this delivery.
