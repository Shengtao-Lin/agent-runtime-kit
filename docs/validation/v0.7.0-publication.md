## Independent Release Desk adoption

The application's own manifest, lock and provenance assertion pin the actual wheel URL and digest
above. No unrelated dependency versions changed. It explicitly enables incremental reads while
retaining a 64 KiB initial window; both remain host choices, not new library defaults.

`scripts/validate_release_desk.py --live --report-dir build/release-desk-v070-published` installed
from that independent lock. All fourteen pytest cases passed. Both invoke and stream completed sixty
successive reviews in each history mode, with initial inputs within 64 KiB, actual historical omission
and all 240 transcript messages retained. Direct read-entry counters establish the selected store
path. Recomposition with both a changed mode and a two-byte window replays success without history
reads or new metadata work; a new request uses the changed mode and fails before tool execution.

`RELEASE_DESK_STREAM_HISTORY=false` restores materialized reads while retaining the configured
window. `RELEASE_DESK_CONTEXT_MAX_BYTES=none` disables both selection and incremental consumption,
with complete growing history verified at the invoker. Library downgrades also require removing the
new runtime keyword from host composition.

The public v0.7.0 canary passed six metadata checks, four-message history and idempotent feedback.
A separate CLI process replayed the exact successful result after reducing the window to two bytes
and disabling incremental reads. The metadata check does not itself install or certify release
artifacts; installed-wheel acceptance above establishes artifact behavior.
